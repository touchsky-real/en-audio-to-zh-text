# 🎙️ Audio2LRC: 英文播客/音频自动转中文字幕

> "我想听英文播客的时候发现，这些播客都没有中文字幕，于是就有了这个项目。"

[![Open In Colab](https://colab.research.google.com/assets/colab-badge.svg)](https://colab.research.google.com/github/touchsky-real/en-audio-to-zh-text/blob/main/audio2lrc.ipynb)

## 📖 项目介绍

本项目是一个运行在 Google Colab 上的自动化脚本，旨在将英文音频或视频中的语音快速转换为 **中英对照的 LRC 歌词或 SRT 字幕**，默认生成 LRC。

**为什么选择 LRC 格式？**
对于播客（Podcast）或音频听众来说，LRC 格式比 SRT 更实用。只需将生成的 `.lrc` 文件与音频文件命名一致并放在同一目录下，大多数主流音乐播放器（如 Musicolet, Salt Player等）即可自动识别并滚动显示歌词。

### ✨ 核心特性

- **零成本**: 完全依托 [Google Colab](https://colab.google/) 的免费 T4 GPU 资源运行。
- **极速转录**: 使用 OpenAI 的 **Whisper (Turbo模型)**，转录速度极快且准确。
- **AI 翻译**: 支持接入 OpenAI 兼容格式的 API（如 GPT-4o-mini, DeepSeek 等）进行高质量翻译。
- **并发加速**: 内置多线程并发翻译机制，长音频处理效率高。
- **自动清洗**: 自动处理文件名中的特殊字符，防止转录出错。

### 支持的输入格式

| 类型 | 常见格式 |
| --- | --- |
| 音频 | MP3、WAV、M4A、AAC、FLAC、OGG、OPUS、WMA |
| 视频（需要包含音轨） | MP4、MKV、MOV、WEBM、AVI |

本项目运行本地 Whisper，通过 FFmpeg 读取声音；Step 2 会检查并安装 FFmpeg。视频可以直接输入，无需先转成 MP3，例如设置 `AUDIO_FILENAME = "example.mp4"`。Whisper 只识别音轨中的语音，不分析画面，也不读取画面中的字幕。

上表列出常见格式，并非固定的扩展名白名单。实际支持范围取决于运行环境中的 FFmpeg 能否解码文件内的音轨；没有音轨、文件损坏或音轨编码不受支持时无法转录。

4.  **依次运行四个代码块**：**Step 1 配置参数 → Step 2 准备环境 → Step 3 转录音频 → Step 4 翻译与保存**。API Key 留空时，Step 1 会提示隐藏输入；Step 2 会请求挂载 Google Drive。

Step 3 开始识别后会显示实时进度条，包括百分比、已用时间和预计剩余时间。复制音频、下载或加载模型时会先显示准备日志；直接恢复已有转录时会提示跳过识别。

若想节省 GPU 使用时长，等 Step 3 完成后再切换为 CPU 运行时，然后运行 **Step 1、2、4**。保持 `SAVE_PROGRESS = True` 时，Step 4 会恢复 Drive 中的转录结果，不会重新转录；找不到匹配结果时会提示先运行 Step 3。

### 参数怎么填：第一次先看这里

**所有参数都在笔记本的 Step 1 中修改。** 找到对应行，替换等号右边的内容。文件名、地址、模型名称要放在英文引号内；数字不用引号；`True` 表示开启，`False` 表示关闭，注意首字母大写。行尾 `#` 后面是说明，不用填写。

第一次使用，先填写文件名、确认文件夹，再填好翻译服务的信息，其余参数可以保持默认。下面的示例用于替换 Step 1 中的对应行，改完后需要运行 Step 1 才会生效。

#### 1. 告诉程序处理哪个文件

假设你把 `example.mp4` 上传到了 Google Drive 的“我的云端硬盘 → podcast”文件夹，就这样填：

```python
AUDIO_FILENAME = "example.mp4"                  # 文件叫什么，连同 .mp4 一起填写
DRIVE_FOLDER = "/content/drive/MyDrive/podcast"  # 文件放在哪个文件夹
```

| 参数 | 怎么填写 |
| --- | --- |
| `AUDIO_FILENAME` | 改成 Drive 中的真实文件名，例如 `my podcast.mp3`。保留空格和扩展名，只填文件名。 |
| `DRIVE_FOLDER` | 按准备步骤放到 `podcast` 文件夹就不用改。如果放在“我的云端硬盘 → videos”，改为 `"/content/drive/MyDrive/videos"`。这里填 Colab 中的文件夹路径，不是 Drive 网页链接。 |

#### 2. 告诉程序用哪个服务翻译中文

程序先用 Whisper 把声音识别成英文，再把英文交给你配置的翻译服务。因此有两个模型参数：**`WHISPER_MODEL` 管听声音，`MODEL_NAME` 管翻译中文。**

| 参数 | 是什么 | 怎么填写 |
| --- | --- | --- |
| `API_KEY` | 翻译服务给你的访问密钥，类似调用接口的密码。 | 推荐保留 `""`，运行 Step 1 时按提示输入；输入内容不会显示出来。 |
| `BASE_URL` | 程序向哪里发送翻译请求。 | 从你使用的平台复制“API 地址”或“Base URL”，不是平台首页或聊天网页地址。程序会自动在末尾加上 `/chat/completions`，这里不要重复加。 |
| `MODEL_NAME` | 翻译服务中要使用的模型名称。 | 从同一平台的模型列表复制准确名称。脚本默认是 `"gpt-4.1-mini"`；使用其他平台时，以该平台实际支持的名称为准。 |
| `WHISPER_MODEL` | 把音频或视频中的声音识别成英文的本地模型。 | 默认 `"turbo"`，一般不用改。它不使用上面的翻译 API Key。 |

下面是脚本默认翻译地址和模型的填写示例。使用其他服务商时，**密钥、地址、翻译模型名称要与该服务商匹配**：

```python
API_KEY = ""                             # 运行 Step 1 时再输入自己的密钥
BASE_URL = "https://api.openai.com/v1"    # 使用其他平台时，替换为该平台给出的地址
MODEL_NAME = "gpt-4.1-mini"               # 使用其他平台时，替换为其支持的模型名称
WHISPER_MODEL = "turbo"                  # 负责识别声音，一般保持默认
```

例如，平台给出的完整请求地址是 `https://api.example.com/v1/chat/completions`，这里应填 `https://api.example.com/v1`。这是地址结构示例，`api.example.com` 不能用于实际翻译；也不要给服务商地址盲目添加 `/v1`，按其说明填写。

**只要英文字幕时**，设置 `OUTPUT_CHINESE = False`，翻译服务的三个参数 `API_KEY`、`BASE_URL`、`MODEL_NAME` 可以保持原样，无需填写有效密钥。

#### 3. 选择输出什么字幕

| 参数 | 默认值 | 什么时候改 |
| --- | --- | --- |
| `OUTPUT_FORMAT` | `"lrc"` | 在音乐播放器里看滚动歌词，保留 `"lrc"`；给视频配字幕，改成 `"srt"`。只能填这两个小写值。 |
| `OUTPUT_CHINESE` | `True` | 默认输出英文原文和中文翻译。只要英文时改为 `False`，会跳过翻译服务。 |

例如，给 `example.mp4` 生成中英双语字幕：

```python
OUTPUT_FORMAT = "srt"
OUTPUT_CHINESE = True
```

这会在视频所在文件夹生成 `example.srt`（双语）和 `example_en.srt`（英文）。如果选择 `"lrc"`，则生成 `example.lrc`。设置 `OUTPUT_CHINESE = False` 时，生成的文件都只有英文。

#### 4. 是否保存进度、完成后是否断开

| 参数 | 默认值 | 用大白话解释 |
| --- | --- | --- |
| `SAVE_PROGRESS` | `True` | **建议一直开启。** 记住已经完成的英文识别和成功翻译。下次补译只处理缺少中文的片段，已经成功的不用再翻。 |
| `AUTO_DISCONNECT` | `False` | 默认完成后保持 Colab 连接。改成 `True`，全部字幕翻译成功并保存后会自动断开；还有翻译失败的片段时不会断开。 |

`SAVE_PROGRESS = False` 表示本次不保存、也不读取以前的进度：重跑 Step 4 会重新翻译全部片段；重启运行时后需要重新识别声音。以前的进度文件不会被删除。详细说明见 [累积翻译与进度恢复](docs/progress.md)。

#### 5. 翻译太慢或经常失败时调哪些参数

这三个参数只影响翻译请求，不改变 Whisper 识别声音的速度。

| 参数 | 默认值 | 具体含义 | 什么时候改 |
| --- | --- | --- | --- |
| `MAX_WORKERS` | `3` | 最多同时请求翻译 3 条字幕；设为 `1` 就是一条一条翻。 | 遇到限流时先降到 `1`。越大不一定越快，可能超过接口允许的请求数量。 |
| `MAX_RETRIES` | `2` | 每条失败后最多再试 2 次，加上第一次，合计最多请求 3 次。设为 `0` 就只试一次。 | 偶尔超时或服务出错时可改为 `3`。密钥错误等会直接停止，增加重试不能解决。 |
| `REQUEST_TIMEOUT` | `30` | 连接或等待接口返回数据的超时设置，单位是秒；不是整个视频的处理限时。 | 接口响应慢、日志提示请求超时时，可改为 `60`。重试和等待间隔会让一条字幕的总耗时超过这个值。 |

如果出现大量限流或超时，可以先试下面这组配置；未列出的参数保持原值：

```python
MAX_WORKERS = 1        # 一次只翻译一条，降低请求压力
MAX_RETRIES = 3        # 失败后再试 3 次，合计最多 4 次
REQUEST_TIMEOUT = 60  # 把等待超时设置提高到 60 秒
SAVE_PROGRESS = True  # 保留之前已经成功的结果
```

这组配置可能花更长时间，也不能解决余额不足、密钥无效等问题。具体要调整哪一项，看下方的失败原因说明。

### 改完参数后，运行哪几步？

**只编辑代码不会立即生效，需要重新运行 Step 1。** 下表中的补译和恢复操作默认 `SAVE_PROGRESS = True`，并且文件、识别模型与已保存进度相匹配。

| 你做了什么 | 接下来运行 |
| --- | --- |
| 第一次处理文件 | **Step 1 → 2 → 3 → 4** |
| 参数不变，只想补上失败的翻译 | **Step 4** |
| 改了翻译服务、并发数、重试次数、超时、输出格式或是否输出中文 | **Step 1 → 4** |
| 换了音频/视频、文件夹或 `WHISPER_MODEL` | 当前环境已准备好时，运行 **Step 1 → 3 → 4** |
| Colab 重启、切换到 CPU，或者加载了新版笔记本 | 已有保存的转录时，运行 **Step 1 → 2 → 4**；找不到匹配转录时，需要先运行 **Step 3** |

更换翻译接口或 `MODEL_NAME` 后，已经成功的中文会保留，新配置用于补译剩余片段。

高级用法（一般可以跳过）：笔记本也能从环境变量 `TRANSLATION_API_KEY`、`TRANSLATION_BASE_URL`、`TRANSLATION_MODEL` 读取密钥、翻译地址、翻译模型。普通使用直接修改 Step 1 即可。

### 翻译失败时如何排查

Step 4 的“本轮已处理”包含成功和失败，会分别显示数量；达到 `181/181` 不代表全部翻译成功。“翻译覆盖率”才是累计成功条数，包含复用的已有翻译。

每条片段在重试耗尽后会立即输出片段编号（从 1 开始，对应转录片段）、实际尝试次数和最后一次失败原因。结束时会按最后一次错误汇总失败条数，例如：

```text
翻译失败：片段 3，已尝试 3 次；最后原因：服务端错误（HTTP 503）
本轮已处理：2/2（成功 1，失败 1）
...
失败原因汇总（按每条片段最后一次错误统计）：
  服务端错误（HTTP 503）：1 条
```

| 日志原因 | 排查方向 |
| --- | --- |
| 请求受限（HTTP 429） | 可能是限流或配额不足；先检查服务商配额，再尝试将 `MAX_WORKERS` 降为 `1`。 |
| 请求超时 / 服务端请求超时（HTTP 408） | 检查网络或服务响应速度；可尝试将 `REQUEST_TIMEOUT` 提高到 `60` 秒。 |
| 服务端错误（HTTP 5xx） | 检查服务商状态，稍后重试；必要时增加 `MAX_RETRIES`。 |
| 网络连接失败 / TLS/SSL 连接失败 | 检查网络、域名、代理或证书。 |
| 返回格式异常 / 返回翻译为空 | 接口未返回有效 JSON、缺少 `choices[0].message.content` 文本或文本为空；检查接口与模型是否兼容 Chat Completions。HTTP 200 也可能出现这类失败。 |
| HTTP 401 / 403 | 检查 API Key、账号状态和模型访问权限；此类错误会停止本轮请求。 |
| HTTP 400 / 404 / 422 | 按错误提示检查地址、模型或请求参数；`BASE_URL` 不要包含 `/chat/completions`。此类错误会停止本轮请求。 |

日志只显示错误分类、状态码等诊断信息，不打印 API Key、原始响应正文或请求异常中的敏感内容。HTTP 429 本身不能区分限流和配额不足，仍需查看服务商控制台。

保持 `SAVE_PROGRESS = True`，排查后重跑 **Step 4** 即可补译；修改参数后运行 **Step 1、Step 4**。旧版 Colab 副本不会自动获得新日志：从上方入口打开更新后的笔记本，填回配置并运行 **Step 1、2、4**，即可恢复已保存的转录和翻译进度，无需重跑 Whisper。
