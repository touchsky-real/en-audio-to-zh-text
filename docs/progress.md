# 累积翻译与进度恢复

笔记本只需三步：配置参数、准备环境、开始处理。Step 3 会自动加载公共函数、恢复或执行转录，再翻译并保存字幕。

Step 1 默认配置 `SAVE_PROGRESS = True`。每条翻译成功后，进度会保存到音频所在目录；重跑 Step 3 时，恢复已有转录和中文，只补尚未成功的片段。例如，原来成功 84/282 条，下次只补剩余 198 条。

设为 `SAVE_PROGRESS = False` 可关闭保存与恢复：本次不读取或写入进度文件，重新执行转录和翻译，已有进度文件不会被删除。修改参数后，重新运行 Step 1、Step 3 即可；无需再次安装依赖。

## 进度文件

以 `example.mp3` 为例，会生成：

- `example.mp3.transcript.json`：已完成的英文转录。
- `example.mp3.translations.json`：成功的中文翻译。

正常情况下只需重跑 Step 3。重启 Colab 后，从 Step 1 依次运行三步，即可恢复转录并继续补译。请保留这些进度文件。

恢复时会核对音频文件名、大小、修改时间和转录内容。音频或转录变化后，不会套用不匹配的进度；更换翻译接口或模型仍会保留已有成功翻译，使用新的配置补译。

LRC 和 SRT 共用同一份翻译进度。Step 1 的 `OUTPUT_FORMAT` 默认为 `"lrc"`，改为 `"srt"` 后重新运行 Step 1、Step 3 即可切换格式；开启进度保存时无需重复转录或翻译成功片段。

## 从旧版升级

如果尚无翻译进度文件，新版会读取同名的旧 LRC/SRT。只有其中所有英文字幕和时间戳都匹配当前转录时，才导入已有中文。

请从 README 入口打开新版，填回自己的配置。已有进度文件会自动恢复；如果只剩字幕文件，需要重新转录后匹配，转录不同则无法自动导入。进度文件损坏时会明确报错，不会直接覆盖损坏文件。

保存进度能避免重复请求已经保存的成功片段，但不会解决接口本身的限流或超时。突然终止进程时，尚未写入文件的请求结果仍可能丢失。进度文件包含字幕文本，不包含 API Key。

## 翻译时提示 GPU 没有在使用

Whisper 转录使用 GPU，翻译调用外部 API，所以翻译阶段 GPU 闲置是正常的，可以忽略提示。`AUTO_DISCONNECT` 只在转录、翻译和字幕保存全部成功后断开，有失败片段时不会断开。

若想节省 GPU 使用时长，保持 `SAVE_PROGRESS = True`，看到“转录已就绪”后停止当前任务，手动将运行时类型改为 CPU，再依次运行三步。切换会重启会话，但 Drive 中保存的转录和成功翻译会被恢复，无需重新识别音频。
